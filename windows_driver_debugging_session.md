# Project-M: Windows Virtual Audio Driver Debugging Session

**Date:** June 10, 2026
**Component:** `lampyris-mic.sys` (Windows Virtual Audio Driver)
**Objective:** Resolve persistent driver installation failures on Windows 10 and validate the `IOCTL` communication pipeline with user-mode clients.

## 1. The Issue
The compiled `lampyris-mic.sys` driver was failing to load on a Windows 10 VM (build 19045) with a Device Manager **Code 39** error. The error specifically indicated that the driver was missing a kernel entry point (`STATUS_DRIVER_ENTRYPOINT_NOT_FOUND` / `0xC0000263`), but Device Manager had a string formatting bug (`The %hs device driver could not locate the entry point %hs in driver %hs`) that obscured the exact missing function.

## 2. Investigation and Root Cause
By checking the **Application Popup (Event ID 26)** logs inside the Windows Event Viewer, we pinpointed the exact missing function:
`lampyris-mic.sys cannot find ntoskrnl.exe ExAllocateFromNPagedLookasideList`

### The Technical "Gotcha"
The driver was being compiled using the modern Windows 11 WDK (`10.0.22621.0`). 
1. In standard Windows 10 architectures, `ExAllocateFromNPagedLookasideList` is treated as a `FORCEINLINE` macro baked directly into the driver's code because standard `NPAGED_LOOKASIDE_LIST` allocations were deprecated in favor of `NonPagedPoolNx` (No-eXecute) security standards.
2. However, in **Windows 11 22H2**, Microsoft subtly reverted this behavior in the headers (`#if (NTDDI_VERSION >= NTDDI_WIN10_NI)`), declaring the function as an external `NTKERNELAPI` and exporting it from `ntoskrnl.exe` again.
3. The WDK linked the driver against this Windows 11 export. When loaded on Windows 10, the OS kernel literally lacked the exported function in its `ntoskrnl.exe`, causing an immediate load crash.

## 3. Implemented Fixes
To resolve this without breaking the overarching architecture, several targeted polyfills and environment changes were implemented:

* **Lookaside List Polyfill (`lookaside_polyfill.h`)**: 
  We wrote a custom header file to aggressively `#undef` the WDK's external declarations for `ExAllocateFromNPagedLookasideList` and `ExFreeToNPagedLookasideList`. We replaced them with custom `FORCEINLINE` assembly implementations (utilizing `InterlockedPopEntrySList`), forcing the compiler to bake the memory cache management directly into the driver binary.
* **Legacy Pool Allocation Polyfill**: 
  Replaced Windows 11-exclusive memory allocations (`ExAllocatePool2`) with backward-compatible `ExAllocatePoolWithTag` calls inside `lampyris_core.cpp`.
* **Namespace Collision Safety**: 
  Renamed the internal device object and symbolic link from `\Device\LampyrisMic` to `\Device\LampyrisMic2` to mitigate any potential "ghost device" conflicts caused by previous corrupted driver installations.
* **INF Broadening**: 
  Modified `ComponentizedAudioSample.inx` to target `NTamd64` generally rather than hardcoding strict Windows 10 build versions, ensuring the driver is treated as a true Universal driver.

## 4. Verification and Pipeline Validation
After recompiling the driver in Release and Debug modes, we verified using `dumpbin.exe` that the rogue imports were successfully eliminated from the driver's Import Address Table (IAT).

The user successfully installed the v3 driver on the Windows 10 VM, completely bypassing the Code 39 error.

### Testing the IOCTL Pipeline
To ensure the kernel-to-user-mode communication was secure and functional, a standalone C++ tester (`TestApp.cpp`) was created. The test app successfully:
1. Extracted the 32-byte randomized `SessionToken` generated by the kernel from the Windows Registry (`HKLM\SOFTWARE\Lampyris`).
2. Opened a secure handle to the newly named `\\.\LampyrisMic2` device.
3. Executed the `IOCTL_LAMPYRIS_AUTHENTICATE` handshake, proving to the kernel that the user-mode application possessed the correct token.
4. Delivered a simulated chunk of raw PCM audio using `IOCTL_LAMPYRIS_PUSH_AUDIO`.

## 5. Final Wrap-up
* Updated the Rust PC client (`pc-client/src/audio/windows.rs`) to target the new `LampyrisMic2` endpoint.
* Committed all source code changes, polyfills, and test applications to the local Git repository under the `feat/windows` branch so it can be ported to the Linux Rust compilation environment.
